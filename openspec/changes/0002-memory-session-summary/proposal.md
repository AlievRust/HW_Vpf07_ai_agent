# Проблема
Сейчас долговременная память `memory.json` сохраняет больше контекста, чем нужно, а пользовательский вывод не разделяет основной ответ и краткое резюме для памяти. Кроме того, краткосрочная память сессии не выделена отдельно и не настраивается.

# Цель
Сделать память агента более управляемой:
- в `memory.json` сохранять только краткое резюме и использованные инструменты;
- вынести краткосрочную память в список последних N вопросов текущей сессии;
- добавить настройку показа резюме после ответа через `.env`;
- сделать число вопросов краткосрочной памяти настраиваемым через `.env`.

# Область работ
- `agent/agent.py`
- `agent/run.py`
- `agent/memory.json`
- `agent/.env`
- `README.md`
- `openspec/project.md`

# Вне области
- изменение набора инструментов;
- изменение внешних API;
- добавление БД;
- синхронизация памяти между пользователями;
- хранение полной истории диалога в `memory.json`.

# Пользовательское поведение
- После ответа агент выдаёт основной ответ.
- Резюме для памяти может показываться на экране или скрываться по настройке из `.env`.
- В долговременную память сохраняется только краткое резюме и использованные инструменты.
- В текущей сессии агент учитывает последние N вопросов пользователя.
- N настраивается через `.env`.

# Риски
- Если формат ответа модели будет плохо парситься, понадобится защитный fallback.
- Слишком маленькая краткосрочная память может ухудшить связность ответов.
- Слишком большое значение краткосрочной памяти может утяжелять prompt.

# Критерии приёмки
- `memory.json` больше не содержит полные пользовательские реплики и полный ответ ассистента.
- Резюме сохраняется отдельно от пользовательского ответа.
- Показывать или скрывать резюме после ответа можно через `.env`.
- Число вопросов краткосрочной памяти настраивается через `.env`.
- Агент использует последние вопросы текущей сессии как контекст.
