# Текущее состояние
В репозитории нет исполняемого кода агента. Есть только текстовое описание желаемого поведения и пустой проектный spec.

# Целевое состояние
Появляется CLI-агент, который:
- читает конфигурацию из `agent/.env`;
- подключается к OpenAI-совместимому API через настраиваемый `base_url`;
- использует LangChain для агентной логики и tool calling;
- выбирает инструменты по смыслу запроса;
- умеет выполнять безопасные файловые операции и ограниченные терминальные команды;
- получает погоду через Open-Meteo с предварительным geocoding;
- получает цену криптовалюты через CoinGecko;
- сохраняет краткое резюме диалога в `agent/memory.json`.

# Изменения модели данных
`agent/memory.json` хранит JSON-объект с массивом записей, где каждая запись содержит:
- timestamp;
- user message;
- assistant response summary;
- использованные инструменты;
- краткий итог диалога.

Формат должен быть устойчивым к пустому файлу и к отсутствию памяти при первом запуске.

# Изменения API
Добавляется CLI:
- `python -m agent.run`
- `python -m agent.run "запрос"`

CLI поддерживает:
- интерактивный режим;
- одноразовый запуск с текстом запроса;
- безопасный выход без сохранения лишнего состояния.

# Изменения конфигурации
Поддерживаются переменные среды:
- `OPENAI_API_KEY`
- `OPENAI_BASE_URL`
- `OPENAI_MODEL` с дефолтом `gpt-5.4-nano`
- `WORKSPACE_ROOT` для ограничения файловых операций

Локальный файл `agent/.env` хранит пример или реальные значения, если пользователь их задаст.

# Примечания по БД и миграциям
Нет базы данных и миграций. Память хранится в JSON-файле.

# Обработка ошибок
- Отсутствующий API key или base URL должны давать понятную ошибку.
- Ошибки внешних API должны возвращаться пользователю в кратком виде без падения всего процесса.
- Небезопасные терминальные команды должны отклоняться до запуска.
- Попытки выйти за пределы workspace при файловых операциях должны отклоняться.
- Повреждённый `memory.json` должен обрабатываться с понятной ошибкой или безопасным сбросом, если файл пустой.

# Последствия для безопасности
- Терминальный инструмент не использует shell execution.
- Ввод пользователя не должен напрямую подставляться в shell-строки.
- Файловые операции ограничиваются корнем workspace.
- Секреты не записываются в `memory.json`.
- Логи и ошибки не должны печатать API-ключи.
