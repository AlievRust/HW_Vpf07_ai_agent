# Текущее поведение
Агент запускается из CLI через `python -m agent.run`.
Вся логика ответа, инструментов, памяти и напоминаний живёт в Python-коде, но Telegram-интерфейса нет.

# Целевое поведение
Появляется отдельный Telegram-бот, который:
- работает в polling-режиме;
- использует тот же `TerminalAgent`;
- не создаёт изолированные контексты по пользователям;
- отображает основной ответ и, при необходимости, краткое резюме памяти;
- при наличии просроченных напоминаний показывает их как обычное текстовое сообщение;
- не заменяет CLI, а работает параллельно с ним как альтернативный вход.

# Затронутые модули и файлы
- `agent/telegram_bot.py` или новый entrypoint-модуль;
- `agent/agent.py`;

# Изменения модели данных
Новая модель данных не требуется.
Telegram-бот использует существующие:
- `memory.json`;
- `reminders.json`;
- session memory текущего процесса.

# Изменения API
Добавляется Telegram entrypoint.
Планируется зависимость `python-telegram-bot`.

Предполагаемые переменные окружения:
- `TELEGRAM_BOT_TOKEN` - токен бота;
- существующие `OPENAI_*`, `WORKSPACE_ROOT`, `SHOW_MEMORY_SUMMARY`, `SHORT_TERM_MEMORY_LIMIT` остаются без изменений.

# Изменения конфигурации
- Бот запускается только при наличии `TELEGRAM_BOT_TOKEN`.
- Polling выбран как режим запуска по умолчанию.
- Отдельный конфиг для webhook не добавляется.

# Обработка ошибок
- Если токен Telegram не задан, бот должен завершаться с понятной ошибкой.
- Если Telegram API недоступен, запуск должен падать с читаемым сообщением.
- Если ответ агента слишком длинный, бот должен разрезать или сокращать сообщение до допустимого размера Telegram.
- Если возникает ошибка ответа агента, бот должен отправить пользователю понятную ошибку, а не падать молча.

# Последствия для безопасности
- Не добавляется пользовательская изоляция по chat id, это намеренно.
- Бот не получает дополнительных shell-прав.
- Доступ к файловой системе остаётся ограниченным существующими правилами агента.
