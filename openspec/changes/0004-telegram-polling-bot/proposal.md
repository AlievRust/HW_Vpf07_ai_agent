# Проблема
Сейчас агент доступен через CLI, но нет Telegram-интерфейса. Из-за этого пользователю нужно работать только через терминал, хотя сам агент уже умеет отвечать, выбирать инструменты и хранить память.

# Цель
Добавить Telegram-бота как второй интерфейс к тому же агенту, не убирая CLI и не вводя многопользовательское разделение контекста.

# Область работ
- `agent/telegram_bot.py` или эквивалентный модуль входа
- `agent/agent.py`
- `agent/run.py` только если потребуется общий helper
- `agent/*.py` для общих форматтеров или вспомогательных функций
- `pyproject.toml`
- `README.md`
- `openspec/project.md`
- `tests/*`

# Вне области
- webhook-деплой;
- многопользовательские профили;
- пользовательские чаты с изолированной памятью;
- перенос логики агента в отдельный backend;
- отказ от CLI.

# Пользовательское поведение
- CLI продолжает работать как раньше.
- Telegram-бот запускается отдельно в polling-режиме.
- Сообщения из Telegram проходят через тот же агентный core и те же инструменты.
- Контекст остаётся общим, без раздельных состояний по Telegram user id.
- Ответы и напоминания отображаются в Telegram в удобном текстовом виде.

# Риски
- Если CLI и Telegram работают одновременно в разных процессах, краткосрочная память процесса будет различаться.
- Общий контекст может смешивать сообщения от разных отправителей, потому что изоляция пользователей не вводится намеренно.
- Telegram-API и ограничения на длину сообщений могут потребовать аккуратного форматирования ответа.

# Критерии приёмки
- CLI не сломан и запускается как прежде.
- Telegram-бот запускается в polling-режиме.
- Бот отвечает через существующий агентный core.
- Не вводится per-user memory.
- README объясняет, как запускать оба интерфейса.
